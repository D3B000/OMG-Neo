# GitHub 请求选路

Neo 的 `OMGLite/src/omg/core/download.py` 使用真实 GET 请求选择通道，不再访问 YouTube，也不在下载前发送 HEAD/Range 探测请求。

## 默认策略

- 首次使用原始 URL，遵循系统代理设置；800 毫秒内未成功时启动下一通道。请求立即失败时立即回退。
- 原始 URL、镜像及绕过系统代理的直连通道参与延迟竞争。单次选路最多运行 3 个请求；达到上限后等空位再启动后续通道。
- 初始顺序为：原始地址的系统代理通道、首个镜像、原始地址的显式直连、后续镜像。未配置系统代理时不重复创建直连通道。
- 缓存成功的镜像前缀和传输通道 5 分钟。缓存键包括目标主机、API/raw/Release/其他内容类型、是否允许镜像、系统代理配置快照。缓存只改变优先级，始终保留其他回退通道。
- 请求失败立即淘汰对应缓存。`reset_route_cache()` 可在切换 VPN/网络时手动清空；`reset_youtube_cache()` 保留为兼容别名。
- 缓存存在进程内。系统代理变化自动使用不同缓存键；无法通过代理配置发现的网络变化依靠失败、TTL 或主动重置处理。

## 成功条件与写入

文本完成读取和 UTF-8 解码后选中；JSON 还必须完成解析。API 限流继续通过 `RateLimitedError` 透传，下载接口将其转换为失败提示并停止重试。

下载先竞争状态码、响应范围和首块数据，只有选中通道由调用线程写目标文件。失败通道不碰文件，迟到响应自动关闭。已下载内容通过实际 GET 的 Range 头续传；200 响应覆盖旧内容；206 必须匹配续传偏移和文件总长。416 只有服务端确认总长恰好等于本地文件长度时才算完成。GitHub 下载响应中的 HTML 错误页面会被拒绝。

传输中断会失效该通道缓存，通过其他通道续传。全部失败后最多重试两轮，退避期间支持取消。仅完整下载成功后才缓存通道。自动选路均验证 TLS 证书。

## 运行边界与验证

800 毫秒是启动回退的间隔，不是整个请求的完成时限。连接/读取使用调用者传入的 timeout。urllib 无法跨线程强制中止正在执行的 DNS、连接或阻塞读取，所以取消或选出赢家后不等待这些工作线程，迟到结果自行释放。已选中并正在写入的下载在读取返回后检查取消。

19 项新增回归覆盖慢连接竞争、失败/过期/网络缓存、取消、并发上限、限流、无效 JSON/HTML、续传、中断后换源、416 校验，以及本地 HTTP 服务上的真实重定向和续传。在 OMG-Neo 目录运行：

```powershell
python -m unittest discover -s backend/tests -p test_download_routing.py -v
```
