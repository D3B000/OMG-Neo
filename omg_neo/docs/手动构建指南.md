# OMG-Neo Windows 手动构建指南

核对日期：2026-10-26。适用于当前源码；如果脚本后续有变化，以实际脚本为准。

推荐使用 `omg_neo/build_release.ps1`。虽然文件名包含 release，它已经支持 `-Configuration Debug` 和 `-Configuration Release`，会构建 Flutter 前端并打包完整 Python 后端。只执行 `flutter build windows` 不等于得到完整分发包。

## 1. 构建结果与模式

| 模式 | UI 调整工具 | 使用场景 | Flutter 中间目录 |
| --- | --- | --- | --- |
| Debug | 显式启用 `OMG_UI_REVIEW=true` | 本机调试、F8 截图批注 | `build-distribution-debug/windows/x64/runner/Debug` |
| Release | 显式关闭 `OMG_UI_REVIEW=false` | 常规分发 | `build-distribution-release/windows/x64/runner/Release` |

两种模式均包含 `backend/omg_backend.exe`、`backend/omg_injector.exe` 和共享 `_internal`。这里的 Debug 指 Flutter 模式；当前 Python spec 中两个 EXE 都设置为 `debug=False`，不会因此变成 PyInstaller 调试启动器。

Debug 使用 Windows 调试运行库，优先在已有开发环境的本机使用；跨机器交付优先选择 Release，并在目标环境验证运行库。无论哪种模式，均须分发整个应用目录，不能只复制 EXE。

## 2. 所需目录与工具

源码布局应保留：

```text
OMG-RE/
  OMGLite/src/omg/                   # 复用业务模块和 loader 原生资源
  OMG-Neo/
    backend/
      main.py
      injector_main.py
      backend_runtime.py
      neo_hosts.spec
      build.ps1
      vendor/ritual/                 # 仪式原生资源
    omg_neo/
      build_release.ps1
      pubspec.yaml
      pubspec.lock
      krr.ico
      fonts/Saira.ttf
      windows/
      lib/
```

工具要求：Windows x64、PowerShell、Flutter Windows SDK、Visual Studio C++ 桌面开发工具与 Windows SDK、Python 3.11 x64 及项目依赖。Flutter 的 Windows 工具链检查以 `flutter doctor -v` 为准。

本机已有路径：

- Flutter：`F:\flutter\bin\flutter.bat`
- Dart：`F:\flutter\bin\dart.bat`
- Python：`F:\Python\Python311\python.exe`
- 应用源码：`G:\ObjNotFound\Tool4game\Landfill\OMG-RE\OMG-Neo\omg_neo`

其他机器需替换以上路径。`pubspec.yaml` 当前版本为 `0.0.2+2`（2026-10-27），Dart SDK 约束为 `^3.6.0`；SDK 是否兼容还取决于当前插件和 Windows runner，不能仅凭该下限判断。下文包名中的旧版本示例需随项目版本调整。

## 3. 初始化 PowerShell 和检查环境

以下代码块按顺序在同一个 PowerShell 窗口执行。每次外部命令执行后检查退出码；PowerShell 的 `$ErrorActionPreference` 不能代替原生命令退出码检查。

```powershell
$ErrorActionPreference = 'Stop'
$appRoot = 'G:\ObjNotFound\Tool4game\Landfill\OMG-RE\OMG-Neo\omg_neo'
$flutterExe = 'F:\flutter\bin\flutter.bat'
$dartExe = 'F:\flutter\bin\dart.bat'
$pythonExe = 'F:\Python\Python311\python.exe'
Set-Location -LiteralPath $appRoot

& $flutterExe --version
if ($LASTEXITCODE -ne 0) { throw 'Flutter 版本检查失败' }
& $flutterExe doctor -v
if ($LASTEXITCODE -ne 0) { throw '请先修复 Flutter 工具链' }
& $pythonExe -c "import sys,struct; print(sys.version); print('bits:',struct.calcsize('P')*8)"
if ($LASTEXITCODE -ne 0) { throw 'Python 检查失败' }
& $pythonExe -m PyInstaller --version
if ($LASTEXITCODE -ne 0) { throw '缺少 PyInstaller' }
& $pythonExe -c "from PySide6.QtCore import QCoreApplication; import requests, PIL, psutil, pefile; print('Python dependency imports OK')"
if ($LASTEXITCODE -ne 0) { throw 'Python 依赖导入失败' }
```

当前后端仍依赖 QtCore；不要为了减小体积直接卸载或排除整个 PySide6。`OMGLite/pyproject.toml` 没有列出完整运行依赖，项目也没有统一的 Neo Python 锁定清单。上述导入检查只是基础检查，不能证明全部动态依赖齐备。

本机核对到的部分依赖版本如下，仅作环境参考，不是完整锁文件：PyInstaller 6.16.0、pyinstaller-hooks-contrib 2025.9、PySide6 6.10.0、requests 2.32.4、Pillow 11.3.0、psutil 7.0.0、pefile 2024.8.26、pywin32 311。复用已验证环境优于直接升级全套依赖；迁移环境时还须检查 loader、ritual 的 DLL/PYD 和 Python ABI。

若 PowerShell 阻止本地脚本执行，可在确认脚本来源后，仅对当前窗口设置：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

无需修改全局执行策略。若机器有组织策略限制，按实际策略处理。

## 4. 准备 Flutter 依赖与构建前检查

统一构建脚本使用 `--no-pub`，因此首次构建、更新依赖或缺少 `.dart_tool/package_config.json` 时，先执行：

```powershell
& $flutterExe pub get
if ($LASTEXITCODE -ne 0) { throw 'Flutter 依赖准备失败' }

& $flutterExe analyze
if ($LASTEXITCODE -ne 0) { throw '静态检查失败' }

& $flutterExe test --dart-define=OMG_UI_REVIEW=true --no-pub
if ($LASTEXITCODE -ne 0) { throw 'Flutter 回归失败' }

& $pythonExe -m unittest discover -s ..\backend\tests -p 'test_*.py'
if ($LASTEXITCODE -ne 0) { throw '后端回归失败' }
```

`pub get` 可能访问网络；已有兼容缓存且必须离线时，可改为 `pub get --offline`。保留 `pubspec.lock`，不要用 `pub upgrade` 代替依赖准备。测试使用夹具或临时目录，不能据此声称真实游戏注入成功。

构建 Release 时额外检查 UI 调整入口被关闭：

```powershell
& $flutterExe test test/distribution_ui_test.dart --dart-define=OMG_UI_REVIEW=false --no-pub
if ($LASTEXITCODE -ne 0) { throw 'Release UI 调整工具隐藏检查失败' }
```

## 5. 一键构建完整 Debug 包

使用带时间戳的新包名，避免与已有目录和 ZIP 冲突：

```powershell
$buildStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$packageName = "OMG-Neo-v0.0.1-debug-$buildStamp"
$destinationRoot = Join-Path $appRoot 'dist\manual'
$packageRoot = Join-Path $destinationRoot $packageName

& .\build_release.ps1 -Flutter $flutterExe -Python $pythonExe `
  -Configuration Debug -PackageName $packageName `
  -DestinationRoot $destinationRoot
```

正常结束会打印“完整应用”。该脚本已检查前后端构建退出码，失败时会抛出错误。输出位置是 `$packageRoot`，此时**还没有自动生成 ZIP**。

完整前后端组装后，脚本还调用 `updater/main.py --create-manifest`，按 pubspec 版本和当前模式生成 `update-manifest.json`，包含程序文件大小与 SHA-256，供独立 TUI Updater 校验。请保留源码中的 `updater` 目录。

## 6. 构建完整 Release 包

与 Debug 顺序执行，不要同时运行：两者仍会共用 Flutter 生成文件及后端打包中间目录。

```powershell
$buildStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$packageName = "OMG-Neo-v0.0.1-$buildStamp"
$destinationRoot = Join-Path $appRoot 'dist\manual'
$packageRoot = Join-Path $destinationRoot $packageName

& .\build_release.ps1 -Flutter $flutterExe -Python $pythonExe `
  -Configuration Release -PackageName $packageName `
  -DestinationRoot $destinationRoot
```

`-PackageName` 只接受单个目录名，不能含路径分隔符。主脚本拒绝已有包目录；后端脚本拒绝非空后端输出目录。遇到失败半成品，改用新包名重建，不要覆盖旧包或把旧依赖混入新包。

## 7. 验包并生成 ZIP、SHA-256 与报告

优先在启动 GUI 之前验包。GUI 启动后会在程序旁生成 AppData，洁净分发审计将失败。检查、压缩和运行验证一体化脚本为 `validation/verify_distribution_v001.py`：

```powershell
New-Item -ItemType Directory -Path (Join-Path $appRoot 'validation') -Force | Out-Null

# Debug 使用此命令
& $pythonExe .\validation\verify_distribution_v001.py $packageName $destinationRoot --debug
if ($LASTEXITCODE -ne 0) { throw 'Debug 验包或压缩失败' }

# Release 改用下面这条，不带 --debug；不要对同一个包重复执行两条
# & $pythonExe .\validation\verify_distribution_v001.py $packageName $destinationRoot
# if ($LASTEXITCODE -ne 0) { throw 'Release 验包或压缩失败' }
```

该脚本要求目标根目录位于应用 `dist` 内。`--debug` 必须位于“包名、分发根目录”两个位置参数之后。它会：

1. 检查前端、双后端 EXE、内嵌图标及注入端依赖隔离。
2. 检查前端编译时间不早于当前 Dart 源码，以及 UI 调整标记是否符合模式。
3. 拒绝配置、AppData、日志、备份、PDB 等污染项。
4. 用临时数据目录验证冻结服务握手、默认配置、保存和退出，并检查没有提前启动注入端。
5. 写入／覆盖包内 `README.txt`，生成 ZIP、校验 ZIP CRC、生成 SHA-256 和 JSON 报告。

生成位置：

```text
dist/manual/<包名>/
dist/manual/<包名>.zip
dist/manual/<包名>.zip.sha256
validation/distribution-<包名>.json
```

注意：验证脚本文件名为历史名称 `verify_distribution_v001.py`，版本文字和报告现从 pubspec.yaml 读取，并核对 Windows EXE 版本。生成最终 README 后会重新生成并验证更新清单。已有同名 ZIP 会导致失败；不要为重复验包直接覆盖正式归档。

## 8. 启动与人工检查

推荐先完成归档，再从 ZIP 解压出独立验收副本。也可直接启动包目录，但该目录随后含运行数据，不再是原始洁净分发目录。

```powershell
Start-Process -FilePath (Join-Path $packageRoot 'omg_neo.exe') `
  -WorkingDirectory $packageRoot
```

此处有意打开可交互窗口。依次检查：首页、浏览、工具、设置；浅深外观；Debug 中 F8、标题栏入口和模态弹窗批注；Release 中这些入口应隐藏。确认退出后该验收副本的后端正常结束。需要实际切服、写回或启动游戏的检查，应使用明确选定的测试数据和任务范围，不能用正常启动检查代替。

`launch.ps1` 当前仍指向 `dist/OMG-Neo/omg_neo.exe`，不会自动运行刚构建的自定义包；请使用上面的绝对目标。默认配置在新包自己的 `AppData` 中，不会自动继承旧包。工作目录也决定默认 `ui-reviews` 等相对导出位置。

## 9. 分阶段构建与排错

仅排查 Flutter 编译时，可按统一脚本的方式隔离设置：

```powershell
$configuration = 'Debug'  # Release 时同时调整模式与开关
$buildDirectory = 'build-distribution-debug'
$preferenceRoot = Join-Path $appRoot '.build-tools\Debug'
New-Item -ItemType Directory -Path $preferenceRoot -Force | Out-Null
$settingsJson = @{ 'build-dir' = $buildDirectory; 'enable-windows-desktop' = $true } | ConvertTo-Json -Compress
[IO.File]::WriteAllText((Join-Path $preferenceRoot '.flutter_settings'), $settingsJson, [Text.UTF8Encoding]::new($false))
$savedAppData = $env:APPDATA
try {
  $env:APPDATA = $preferenceRoot
  & $flutterExe --suppress-analytics --no-version-check build windows --debug `
    --dart-define=OMG_UI_REVIEW=true --no-tree-shake-icons --no-pub
  if ($LASTEXITCODE -ne 0) { throw 'Flutter Debug 构建失败' }
} finally {
  $env:APPDATA = $savedAppData
}
```

Release 对应 `.build-tools/Release`、`build-distribution-release`、`--release` 和 `OMG_UI_REVIEW=false`。只在 Flutter 调用期间更改 APPDATA，并在 finally 恢复；不要设置成应用运行数据目录，也不要修改用户全局 Flutter build-dir。

仅排查后端打包时，明确指定新的空输出目录；不省略 `-Output`，因为其默认值仍是旧的 `build/windows/.../Release/backend`：

```powershell
$backendOutput = Join-Path $appRoot ('validation\backend-only-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
& ..\backend\build.ps1 -Python $pythonExe -Output $backendOutput
```

正式流程调用 `neo_hosts.spec`，不要改回旧 `omg_backend.spec`，也不要简单复制服务 EXE 充当注入端。手动组装前端时只复制 `data`、应用 EXE、DLL 和可选 `native_assets.json`，然后把完整后端放在 `backend`；用于现有验包脚本的包不含 PDB。

| 现象 | 处理 |
| --- | --- |
| 找不到 Flutter／Python | 使用本文显式工具路径，其他机器自行替换 |
| 缺少依赖或 package_config.json | 执行 pub get，检查 Python 环境和相邻 OMGLite 目录 |
| Windows C++ 工具链不可用 | 修复 doctor 报告的 Visual Studio／SDK 配置 |
| 包目录已存在／后端目录非空 | 换新包名或新的空输出目录 |
| 文件被占用 | 关闭对应构建产物；不要结束其他包、游戏或无关进程 |
| PyInstaller 输出 INFO 到 stderr | 以退出码和最终错误判断；现有脚本已处理 PowerShell 偏好设置 |
| Frontend sources changed after compilation | 重新编译前端，再重新打包，避免混合不同时间的源码 |
| Debug/Release review marker 检查失败 | 检查构建模式、显式开关和所复制的前端目录 |
| 隐私审计失败 | 不打包已使用目录中的 AppData；重新生成洁净包 |
| 打包失败后留下部分目录 | 保留日志，换新目标重试；不要把半成品称为成功包 |

补充架构说明见 `../../backend/PROCESS_MODEL.md` 和 `../../backend/PACKAGING.md`；供 agent 使用的交接流程见 [Agent 构建流程](Agent构建流程.md)。

## 10. 构建独立 TUI 更新器

从 OMG-Neo 根目录执行 `./updater/build.ps1 -Python F:\Python\Python311\python.exe`，生成 `updater/dist/OMG-Neo-Updater.exe` 与校验文件。更新器应放在应用安装目录外；手动添加完整 ZIP 后，会保留数据、备份旧目录并替换程序。详见 [Updater 使用与事务设计](../../updater/README.md)。
